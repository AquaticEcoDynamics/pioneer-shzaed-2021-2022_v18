Pioneer Estuary

This chapter applies the budget framework to the Pioneer estuary: how the control volume is defined, and what the nitrogen budget returns for the flood run.

The control volume

A budget is computed over a control volume (CV) — a contiguous set of mesh elements whose seaward boundary coincides with the Pioneer Mouth flux transect and which is otherwise closed by land and the upstream river. For run 003 the CV is 16,344 elements (4.81 km²) and contains all three river point sources.

How the CV is built — three steps, and the files to cross-check or remake it. (1) A polygon is drawn around the estuary in lon/lat and saved as cv_pioneer_estuary.csv; its seaward edge follows the Pioneer Mouth flag 2↔︎3 transect — the line where fluxflag.prop region-2 faces meet region-3 faces — so the CV boundary lands exactly on the flux-tracked gate. (2) build_cv.py reads the mesh (hgrid.gr3) and selects every element whose centroid falls inside the polygon (point-in-polygon), writing the 1-indexed element-ID list cv_pioneer_estuary_elements.txt — the exact array every budget script integrates over. (3) cv_definition_map.py overlays that element list on the mesh, the fluxflag.prop flags and the source_sink.in inflows (Figure 1) so the selection can be verified. To define a different CV, redraw the polygon CSV and re-run steps 2–3; the inputs are just hgrid.gr3, cv_pioneer_estuary.csv, fluxflag.prop and source_sink.in.

The region config (YAML)

The region YAML names the CV element list and the bounding fluxflag.prop regions with their sign conventions (configs/pioneer_estuary.yaml):

name: pioneer_estuary
control_volume_elements: cv_pioneer_estuary_elements.txt
boundary_fluxes:
  - region_id: 3
    sign: +1
    label: "Pioneer Mouth (region 3 -> region 2): positive = bay -> estuary, INTO CV"
integrate_atm_over_cv: true
integrate_swi_over_cv: true

Boundary tracking caveat

A critical subtlety for the boundary term: flux.out records transport only across mesh edges where the two adjacent fluxflag.prop values differ by exactly 1 and neither is −1. If part of the CV perimeter is the (−1, region) interface or a same-flag edge, transport through it is invisible to the budget. This turns out to be the heart of the Pioneer mouth problem.

The Pioneer nitrogen budget

Running the framework over this CV for the 14-day flood window produces the standard outputs. The stacked-area plot shows the instantaneous balance of terms; the cumulative plot integrates them to tonnes of nitrogen.

The conservative checks come first. Volume and salinity should close tightly; if they do not, the nutrient terms cannot be trusted. The conservative tracers (GEN_1, TRC_tr1) give a second, source-driven check.

Important

Read this budget with one caveat. Run 002 was produced on an earlier build affected by the “only NCS_ss1 registers” output bug, so its combined AED files contain only the sediment (NCS_ss1) diagnostics — none of the nitrogen rate, sediment–water or atmospheric diagnostics were saved. Terms B (internal sinks), C (atmospheric) and D (sediment–water) are therefore unavailable and set to zero, and the storage term uses a zCoordinates-derived layer thickness in place of ENV_layer_ht. The large residual consequently conflates those genuinely-missing terms with the conservation issues discussed next — it is not a pure closure error. A run on the fixed build that saves the full diagnostic set is needed for a closeable nitrogen budget.

For this run the residual does not close — the storage change far exceeds the tracked source and boundary terms. The forensic account of the conservation issues, and how an independent cross-check confirmed them, is the subject of Conservation Testing.
